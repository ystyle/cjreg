# 性能基准

> 复现：`bash scripts/bench.sh`（桩上游 `scripts/bench-stub-upstream.py` + k6 并发档）。
> 采集脚本、环境与原始输出见仓库 `docs/benchmark.md`。

## 关键结果

| 项 | 结果 | 口径 |
|---|---|---|
| 索引：回源 → 本地命中 | **16.16 ms → 2.74 ms（5.9×）** | 200 次请求；桩计数证明重查轮**零回源** |
| 发布吞吐 | 2 / 32 / 200 MiB = **74 / 278 / 324 MiB/s** | HTTP 上传，单机 loopback |
| 发布峰值内存 | **291 MiB 恒定**（三档一致） | `/proc/<pid>/status` 的 `VmHWM` |
| 200 MiB 制品下载 | 成功，**sha256 一致** | 流式下载，内存平稳 |
| 并发（索引命中态） | 1/4/16/64 VU → **88 / 294 / 414 / 356 req/s** | k6，拐点在 16–64 VU 之间 |

## 为什么这些数字可信

- 上游是**桩服务**（固定 5 ms 延迟），不依赖公网，任何人可复现同一组数；
- 内存取进程 `VmHWM`（峰值常驻），不是估算；
- 索引命中与回源是同一脚本的对照轮次，桩的请求计数直接证明确实没有二次回源。

## 与初赛版本对比

| 指标 | v0.2.0 | v0.3.0 |
|---|---|---|
| 最大可发布包体 | ≤32 MiB 稳定（48–50 MiB 偶发 OOM） | **200 MiB 稳定**（`max_request_bytes` 可配到 500 MiB） |
| 200 MiB 发布 | 失败 | **0.618 s / 291 MiB** |
| 200 MiB 下载 | `Out of memory` | 成功且 sha 一致 |
